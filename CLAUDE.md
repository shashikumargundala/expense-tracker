# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Single-module Android app (`:app`, namespace `com.example`), an offline-first expense tracker that can optionally sync with Google Sheets. It's built with Kotlin, Jetpack Compose, Material 3, Room (KSP), Retrofit/OkHttp/Moshi, minSdk 24, compile/target SDK 36, and Java 11. It was generated by Google AI Studio. `.github/copilot-instructions.md` holds the original detailed conventions. Keep it in sync with this file.

## Commands

Run all commands from the repo root using the Gradle wrapper:

```bash
./gradlew :app:assembleDebug                      # build debug APK
./gradlew :app:testDebugUnitTest                  # all JVM unit tests (incl. Robolectric)
./gradlew :app:testDebugUnitTest --tests "com.example.ExampleUnitTest"                     # one class
./gradlew :app:testDebugUnitTest --tests "com.example.ExampleUnitTest.addition_isCorrect"  # one method
./gradlew :app:connectedDebugAndroidTest          # instrumentation tests (device/emulator)
./gradlew :app:lintDebug                          # Android lint
```

- `GreetingScreenshotTest` uses Robolectric + Compose test rules + Roborazzi and writes `app/src/test/screenshots/greeting.png`.
- **Debug signing:** the `debug` build type uses `signingConfigs.debugConfig`, which points to `${rootDir}/debug.keystore`. That file isn't in the repo, so debug builds fail until you add the keystore or remove the `signingConfig = signingConfigs.getByName("debugConfig")` line from `app/build.gradle.kts` (the README describes this step). Release signing reads `KEYSTORE_PATH`, `STORE_PASSWORD`, and `KEY_PASSWORD` from the environment.
- **Secrets:** the Secrets Gradle Plugin reads `.env` and falls back to `.env.example`. These values are exposed via `BuildConfig`. The README requires `GEMINI_API_KEY`, but the Firebase AI dependency is currently commented out and no app code uses it.

## Architecture

There's no DI framework. `MainActivity` wires everything by hand: `AppDatabase.getDatabase()` → `ExpenseRepository` → `ExpenseViewModel`. It then shows either `LoginScreen` or `MainAppContent`.

- **UI (`MainActivity.kt`, about 1,900 lines):** nearly all composables live in this one file (login, main content, dialogs, Sheets card, analytics, budget alerts, filters, rows). The theme is in `ui/theme`. Composables read state from the ViewModel and call ViewModel actions. They don't duplicate DB state; Room flows drive recomposition.
- **`ui/ExpenseViewModel`:** owns UI state. It converts DAO `Flow`s with `stateIn(viewModelScope, SharingStarted.WhileSubscribed(5000), …)` and launches repository work in `viewModelScope`. Budget analytics are derived from the expense flow: spend is grouped by category name, and alerts fire at 80% (`WARNING`) and 100% (`CRITICAL`) of a positive category budget.
- **`data/ExpenseRepository`:** the single data boundary.
  - Room access runs in `withContext(Dispatchers.IO)`.
  - Default categories are bootstrapped here.
  - Session and sync settings (spreadsheet ID, OAuth/refresh tokens, Google client ID/secret, user name/email) live in `SharedPreferences` (`expense_tracker_prefs`), exposed as repository properties. Don't read prefs from UI or the activity.
  - OAuth code-for-token exchange and refresh are done here with raw OkHttp.
- **Room (`AppDatabase`, `ExpenseDao`, `CategoryDao`):** DB `expense_tracker_db`, version 1, `exportSchema = false`, no migrations defined. Any entity change requires a version bump plus a migration (or a deliberate destructive fallback). `CategoryEntity.name` is the primary key, so category names must be unique.
- **Sheets sync (`GoogleSheetsService`, `RetrofitClient`):** Retrofit wrapper over the Sheets REST API.
  - New expenses are saved with `synced = false` and pushed immediately only if a spreadsheet ID and token exist. `syncLocalToSheets()` pushes the remaining unsynced rows, and `pullDataFromSheets()` imports rows from the sheet.
  - Only mark a row synced after a successful Sheets write. Local writes must succeed even when the network fails, with failures surfaced through `syncMessage` and logging.
- **OAuth redirect:** the `com.example.expensetracker://oauth2callback` deep link returns to `MainActivity.handleIntent`. Keep the scheme and host unchanged.

## Conventions

- Put new persistence and sync logic in the repository or data layer, not in composables.
- Interactive controls use `testTag`. Keep existing tags, and add tags to new user-critical actions.
- Dependencies go through `gradle/libs.versions.toml` aliases. Don't hard-code versions in `app/build.gradle.kts`. Unused libraries are intentionally left commented out in `app/build.gradle.kts` rather than removed.

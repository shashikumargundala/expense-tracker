- (decision) Paradigm: Clean Architecture as three Gradle modules — :domain (pure Kotlin/JVM, no Android), :data (implements domain interfaces), :app (Compose UI + ViewModels). Binds all code; prevents UI/data leaking into domain (compiler-enforced). Chosen over single-module (unenforced) and feature modules (overkill now)
- (decision) Inside each module, packages by feature (expense, budget, inbox, account, ...). Features interact only via domain interfaces, never another feature's internals — keeps a later split into :feature:* modules mechanical
- (decision) Data ownership: Room is a local mirror the UI always reads; local writes go to Room + an outbox; a single sync engine pushes the outbox and pulls the whole Expense Sheet into Room, Sheet wins conflicts. Prevents screens reading Sheets directly and multiple writers to the Sheet
- (decision) Identity: every Expense has a UUID stored in an ID column of the Sheet (replaces local autoincrement 'Local ID'; current code maps unparseable IDs to 1 and overwrites expense #1). Sync assigns a UUID and Source=User to hand-typed rows lacking an ID and writes them back; duplicate IDs (copied rows) keep the first and reassign the rest
- (decision) Money: amounts are Long minor units (paise) in domain and Room; the Sheet shows human-readable decimal rupees and the sync converts both ways
- (decision) Sync triggers: app open, return to foreground, pull-to-refresh, and connectivity regained via WorkManager (network-constrained job pushing the outbox even when app closed)
- (decision) Auth: Credential Manager (Sign in with Google) for sign-in; AuthorizationClient for Drive/Sheets access with the drive.file scope only. Replaces simulated login and the custom-scheme deep-link + client-secret flow. Prevents broad sensitive scopes and secrets on device
- (decision) Tokens: only short-lived access tokens from AuthorizationClient, re-requested silently on expiry; no refresh token or client secret stored on the device (satisfies NFR-5)
- (decision) Boundary: domain defines AccountGateway (signed-in user, get access) and ExpenseSheetGateway (read/write Sheet); all Google SDK/REST code lives in :data behind them so tests use fakes

- (decision) SMS parsing: BankSmsParser strategy interface in :domain (pure Kotlin) with one parser per bank (HDFC, ICICI, SBI, Union Bank, ...) plus GenericDebitParser fallback; ParserRegistry selects by SMS sender. - (decision) Sync contract (fixes push-before-pull hole): each outbox entry stores its base (row values at last pull, or absent). A run reads all tabs fresh, locates rows by key never by index; if row differs from base the Sheet wins and the entry is dropped; otherwise applied idempotently (create on existing ID = update; delete missing = no-op); entries removed only after write confirmed; then mirror refresh
- (decision) Mirror refresh: only after all tabs read successfully, one Room transaction applying a diff merged with still-pending outbox entries, never clear-then-insert; Pending Sync derived from outbox presence
